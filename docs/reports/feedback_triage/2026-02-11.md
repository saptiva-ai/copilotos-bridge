### Patron D — Chart Year Mismatch / STALE (S0) — 25 charts
**Charts afectados:** SC-2, SC-4, SC-5, SC-7, SC-9, SC-10, SC-12, SC-14, SC-15, SC-17–20, SC-41–44, SC-47–50, SC-53–56, SC-59–62
**Ticket:** `chart-year-mismatch` (In Progress, 3ra reapertura)

**Sub-patrones:**
1. **Missing {2025}** (SC-2, 7, 12): x_range `[2024-01-01, 2024-12-01]` — handler genera solo 2024
2. **Missing {2024}** (SC-5, 10, 15, 17, 41, 47, 53, 59): x_range comienza en `2023-11` — incluye Nov 2023 pero no muestra puntos explícitos de 2024
3. **Missing {2024, 2025}** (SC-4, 9, 14): x_range `[AFIRME, SISTEMA]` — chart eje X tiene nombres de bancos en vez de fechas (chart horizontal de barras mal formateado)
4. **Missing {2024}** (SC-18–20, 42–44, 48–50, 54–56, 60–62): x_range `[2025-01-01, 2025-10-01]` — solo 2025

**Hipótesis raíz:** El handler de evolución recibe `date_start`/`date_end` del parser, pero cuando el usuario dice "enero 2024 vs enero 2025", el `_ensure_multi_year_coverage()` expande el rango a un continuo `[2024-01-01, 2025-12-31]`. Esto genera una línea temporal completa en vez del par puntual que el usuario espera. El problema real es que no existe un handler para **comparación puntual** (mes A del año X vs mes A del año Y) — el sistema siempre genera evolución temporal continua.

**Sub-patrón SC-4/9/14:** El eje X muestra `[AFIRME, SISTEMA]` (nombres de banco), indicando que se generó un bar chart horizontal con bancos en eje X en vez de un line chart con fechas. Probable causa: el handler de NL2SQL interpreta la query como ranking en vez de evolución.

**Severidad:** S0 (gráfica no muestra los datos solicitados)
