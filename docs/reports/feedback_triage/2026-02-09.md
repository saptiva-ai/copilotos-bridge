## 1) Resumen ejecutivo

Dos problemas sistémicos generan la mayoría del feedback negativo:

1. **STALE_CHART (S0 — Crítico)**: Cuando los usuarios solicitan métricas financieras para un año específico (ej. "cartera comercial de INVEX en 2025"), el pipeline SQL retorna datos sin filtros de fecha, resultando en gráficas con datos de otro año. Ha ocurrido **9 veces en 7 días** y causa **4 de 8 thumbs-down hoy**.

2. **CATALOG_FALLBACK (S1 — Alto)**: Cuando el fast path de catálogo retorna un `response_text` (ej. "No se encontró banco con clave 040032"), la capa de persistencia escribe una **plantilla genérica** ("A continuación se presentan los datos...") en `message.content`. El usuario ve el mensaje incorrecto. **3 instancias en 7 días**.

Adicionalmente:
- **STATE_LEAK**: El contexto de conversación filtra nombres de bancos entre turnos (INBURSA apareció en una consulta de INVEX vs BANREGIO).
- **CATALOG_MISS**: "IXE" no está en la tabla de lookup; "cual es la de monex?" no pasa por el fast path de catálogo y el LLM alucinó el código incorrecto.

## 5) Hipótesis Raíz + Fix Recomendado

### Cluster 1: STALE_CHART — Missing Date Filter in SQL

**Hypothesis (Confidence: 85%):**
The `build_display_sql()` function in `plugins/bank-advisor-private/src/bankadvisor/utils/sql_display.py` generates the display SQL from `entities.date_start` / `entities.date_end`. These fields are populated by `EntityService._extract_dates()` (Pattern 5: `r'\b(20\d{2})\b'` → `date(year, 1, 1)` to `date(year, 12, 31)`).

However, the display SQL consistently lacks date filters, meaning `entities.date_start` and `entities.date_end` are `None` when passed to `build_display_sql()`. Two possible sub-causes:

**Sub-cause A:** The query goes through `route_and_enrich()` → handler chain. If a handler matches (e.g., via semantic scorer) but returns data without using the entity date range, the display SQL won't reflect dates. The handler may use `spec.time_range` dates for the actual SQL but the enricher uses `entities` for the display SQL.

**Sub-cause B:** The `entities` object passed to `ResponseEnricher.enrich()` is a different or stale instance that doesn't have dates populated.

**Fix:**
1. In `ResponseEnricher.enrich()` (`response_enricher.py:78-84`), fall back to `spec.time_range.start_date` / `spec.time_range.end_date` when `entities.date_start` / `entities.date_end` are None:
   ```python
   date_start = getattr(entities, 'date_start', None) or (
       spec.time_range.start_date if spec and spec.time_range else None
   )
   ```
2. Verify that the actual executed SQL (not display SQL) includes date filters by adding structured logging in `sql_generation_service.py:_generate_timeseries_sql()` at line 400.
3. Add a regression test: "cartera comercial de INVEX en 2025" must return `x_range[0] >= '2025-01-01'`.

### Cluster 2: STATE_LEAK — Bank Names From Prior Turn

**Hypothesis (Confidence: 90%):**
The bank extraction logic accumulates banks from the conversation context. When user says "invex vs banregio" in turn 5, the system still carries "INBURSA" from turn 4 in the spec or entities.

**Fix:**
1. Identify where `spec.bank_names` is being built — check if conversation history/context is merged into the current turn's bank list without clearing.
2. In the `QuerySpecParser._extract_banks_heuristic()`, ensure only banks from the CURRENT user message are extracted, not from prior turns.
3. If the semantic router or handler chain passes session-level context, verify it doesn't merge `bank_names` across turns.

### Cluster 3: CATALOG_FALLBACK — Content vs response_text Mismatch

**Hypothesis (Confidence: 90%):**
The streaming layer writes `message.content` with a generic template BEFORE the catalog fast path result is processed. The catalog returns `response_text` in `bank_chart_data`, but by then the `content` field is already committed.

**Fix:**
1. In the message persistence/streaming handler (likely `apps/backend/src/services/`), check if `bank_chart_data.type == "catalog"` and `bank_chart_data.response_text` is non-null. If so, override `message.content` with `response_text`.
2. Alternative: In the catalog fast path return, set the `content` field directly instead of only setting `bank_chart_data.response_text`.

### Cluster 4: CATALOG_MISS — IXE, Monex, Multi-Bank

**Fixes:**
1. **IXE:** Add IXE (code 0000040032) to `bank_dim_institucion` or the lookup table. Even though IXE was acquired by Banorte, users still reference it.
2. **Monex:** The catalog fast path pattern for "cual es la de {bank}?" is too narrow. Add pattern: `r"(?:cual|cuál)\s+es\s+la\s+(?:clave\s+)?de\s+(.+)"` to catalog matching.
3. **Multi-bank separator:** In `handle_catalog_query()`, split on Spanish connectors: " e ", " y ", " & ", ", " before looking up each bank individually.
