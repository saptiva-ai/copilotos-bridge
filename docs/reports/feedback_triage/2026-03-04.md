## 5) Hipotesis raiz

### FDBK-0194 — ICOR evolución: PROMEDIO = INVEX (S0)

**Query**: Comparar ICOR de INVEX vs promedio de 9 bancos, Oct 2022 → actual.
**Evidencia**: La respuesta muestra "INVEX = 2.37 %, PROMEDIO = 2.37 % (ratio = 1.00x)". El promedio debería incluir MONEX, BANCREA, SABADELL, MIFEL, MULTIVA, AFIRME, BANSI, VE POR MAS, BANCO BASE pero claramente solo incluye INVEX.
**Hipótesis**: `peer_average.py` no encuentra datos de ICOR para los bancos peer. ICOR es un **ratio calculado** (Reservas / Cartera Vencida), no una columna directa en la vista materializada `bank_metrics_mv`. El handler `comparative_ratio` o `metricas_financieras` probablemente busca una columna `icor` que no existe para los peers, o el SQL generado filtra solo por INVEX.
**Componente**: `peer_average.py` → SQL generator → handler de métricas financieras.
**Severidad**: S0 (dato incorrecto presentado como válido).

### FDBK-0193 — ICOR barras: solo INVEX (S0)

**Query**: ICOR Dic 2025 para 10 bancos, barras horizontales.
**Evidencia**: "No se dispone de datos para los demás bancos... solo INVEX". Respuesta: INVEX = 2.37%, resto "No disponible".
**Hipótesis**: Misma raíz que FDBK-0194. El handler de barras horizontales multi-banco para ICOR no sabe calcular el ratio por banco individual. Probablemente hace `SELECT icor FROM ...` pero la columna es `indice_cobertura` o requiere `reservas_preventivas / cartera_vencida`.
**Componente**: Handler `metricas_financieras` o `comparative_ratio` → SQL builder.
**Severidad**: S0.

### FDBK-0192 — ICOR barras: "no me dio el resultado esperado" (S0)

**Query**: Misma que FDBK-0193 pero pidiendo "ICOR 01/2025" (enero).
**Evidencia**: Misma respuesta — solo INVEX a 2.37%. Es la misma falla de ICOR multi-banco.
**Hipótesis**: Idéntica a FDBK-0193. Patrón repetido 3 veces en la misma conversación (`7a72be76`).
**Componente**: Igual.
**Severidad**: S0.

### FDBK-0191 — ICAP barras: solo INVEX (S0)

**Query**: ICAP Dic 2025 para 10 bancos, barras horizontales (conv `3a043584`).
**Evidencia**: "solo se tiene el valor de INVEX", ICAP = 16.38%. Sin embargo, en conv `80656ba9` (14 minutos antes), **la misma query funcionó perfectamente** devolviendo los 10 bancos (BANCREA 18.45%, MIFEL 17.92%, etc.).
**Hipótesis**: Intermitencia. Posibles causas: (1) El primer request pobló cache con data correcta (conv `80656ba9`, handler `metricas_financieras` con todos los bancos), pero al iniciar nueva conversación (`3a043584`) el handler routing cambió (quizá `comparative_ratio` en vez de `metricas_financieras`). (2) Cache de Redis devolvió resultado parcial de un request diferente. (3) El context enricher inyectó "INVEX" como banco contextual y el handler filtró solo por ese.
**Componente**: `query_router.py` (selección de handler) o `context_enricher.py` (inyección de banco).
**Severidad**: S0. **Patrón nuevo**: intermitencia de ICAP (funciona y luego no).

## 5b) Hallazgos adicionales — análisis visual de capturas de pantalla

El usuario (cliente Invex) compartió capturas de pantalla comparando las respuestas del bot contra una **fuente de verdad (presentación PPT)**. Esto reveló bugs no detectables solo con los feedback IDs.

### Bug nuevo 6: Chart renderer omite 1 banco (gráfica ≠ tabla)

**Evidencia**:
- **Tasa ME**: La tabla muestra 10 bancos (incluyendo BANSI=6.49%), pero la gráfica de barras horizontales solo muestra **9 bancos** — **BANSI omitido** de la gráfica.
- **Tasa MN**: La tabla muestra 10 bancos (incluyendo MIFEL=14.38%, el valor más alto), pero la gráfica de barras solo muestra **9 bancos** — **MIFEL omitido** de la gráfica.

**Hipótesis**: El chart renderer (`bank_chart` tool) tiene un límite de trazas o un bug en la construcción de las barras que descarta el último/primer banco. Alternativamente, el MCP tool recibe solo 9 bancos del handler aunque el LLM genera la tabla completa con 10 desde el system prompt context.

**Severidad**: S1 (UX roto — la gráfica contradice la tabla en la misma respuesta).
**Componente**: `chart_renderer` / MCP tool `bank_chart` / handler que alimenta el chart.

### Bug nuevo 7: Valores numéricos divergen de la fuente de verdad (PPT/CNBV)

**Evidencia** (comparando respuesta del bot vs PPT del cliente):

| Banco | Métrica | Bot | PPT (verdad) | Delta |
|-------|---------|-----|-------------|-------|
| BANCO BASE | Tasa ME | 6.99% | 6.88% | +0.11pp |
| INVEX | Tasa ME | 8.26% | 8.08% | +0.18pp |
| BANCO BASE | Tasa MN | 10.44% | 10.37% | +0.07pp |

**Hipótesis**: Dos posibilidades:
1. **Periodo distinto**: La BD tiene el dato de Dic 2025 pero la PPT usa Nov 2025 o un promedio trimestral diferente. El query del usuario dice "Diciembre 2025" pero si la PPT compara contra otro periodo, la divergencia sería esperada.
2. **Fuente de datos distinta**: La BD se carga desde `Informe_Bancos.xlsx` (CNBV R04) mientras que la PPT puede usar una fuente interna de Invex con metodología ligeramente diferente.
3. **Redondeo/ponderación**: La BD almacena `tasa_promedio_mn` como promedio simple pero la fuente oficial puede usar promedio ponderado por saldo.

**Severidad**: S0 si es error de datos; S2 si es diferencia metodológica esperada.
**Componente**: ETL / datos_BD (requiere verificación cruzada con fuente CNBV).
**Acción recomendada**: Validar `SELECT tasa_promedio_me, tasa_promedio_mn FROM bank_fact_kpis_mensual WHERE banco_norm IN ('BANCO BASE','INVEX') AND fecha='2025-12-01'` contra el Excel fuente.
