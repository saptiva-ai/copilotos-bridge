- **Top 3 issues recurrentes:**
  1. **Grounding desync (texto vs datos):** El LLM cita un valor para una fecha pero los datos reales del chart muestran otro. Ej: dice "Oct 2024: 15,052 MDP" pero el dato real de Oct 2024 es 15,499 MDP (confunde con Dic 2024). **3 reportes** (FDBK-0093, 0094, + parcial en 0091).

- **Logros (qué ya funciona):**

## 3) 👎 Issues (agrupados)

### Cluster A: Follow-up queries no rutean al catálogo (NUEVO)

- **Evidencia:**
  - FDBK-0078: "cual es la de monex ?" → respondio 040067 (incorrecto). **Sin `data_returned`** = no paso por catalog fast path, LLM alucino.
  - FDBK-0079: "a que banco pertenece 040067" → "no se encontro" (porque 040067 no existe). **Nota:** `response_text` en root dice "la metrica solicitada" (texto generico de fallback), pero `data_returned.response_text` dice "No se encontro" — hay desync entre response_text del LLM y del tool.
  - FDBK-0085: "cual es la de ssntander ?" → 040012 (clave de BBVA). **Sin `data_returned`** = LLM fallthrough.
  - FDBK-0086: "cual es la de santander ?" → 040012 + menu guia. **Sin `data_returned`** = LLM fallthrough.

- **Hipotesis de causa raiz** (confianza: ALTA):
  El `QueryRouter` detecta catalog queries por keywords ("clave", "institucional", etc.). Pero cuando el usuario usa referencia eliptica como "cual es la de X?" (omite "clave"), el router no la clasifica como catalog → cae al LLM path que genera respuesta sin consultar la DB.

  **Evidencia adicional:** FDBK-0087 ("cual es la clave de santander?") si incluye "clave" explicitamente → pasa por catalog fast path → respuesta correcta. FDBK-0088 ("y la de INVEX?") tambien funciono, lo que sugiere que a veces el follow-up SI funciona (posiblemente por contexto del chat).

- **Como reproducir:**
  1. En chat, preguntar: "cual es la clave de BBVA?" (debe responder correctamente via catalog)
  2. Preguntar: "cual es la de monex?" (debe fallar — no rutea a catalog)

- **Accion recomendada:**
  - **Ticket:** CREATE `2026-02-06__BUG__multi-turn-catalog-routing`
  - **Title:** Follow-up elliptical queries bypass catalog fast path
  - **Description:** When user asks "cual es la de X?" without explicitly saying "clave", QueryRouter doesn't detect it as a catalog query. Falls to LLM which hallucinates bank codes.
  - **Acceptance criteria:**
    - "cual es la de monex?" after a clave question → returns correct 040112 via catalog tool
    - "y la de santander?" → returns 040014
    - Typos like "ssntander" should still resolve to SANTANDER
  - **Severidad:** S1 — respuesta incorrecta frecuente, anula el valor del fix de bank-code-hallucination
  - **Owner sugerido:** backend (QueryRouter / intent detection)
  - **Tests sugeridos:** Add to `test_bank_code_catalog.py`: multi-turn follow-up test case

### Cluster C: Grounding desync texto vs datos (CONOCIDO)

- **Evidencia:**
  - FDBK-0093: "compare cartera de bbva e invex ultimo ano" → Texto dice "INVEX Oct 2024: 15,052.10 MDP". Dato real en chart `y[0]` para `x[0]='2024-10-01'` es **15,499.60**. El valor 15,052 es de `x[2]='2024-12-01'`. El LLM confunde fechas con valores.

- **Hipotesis de causa raiz** (confianza: MEDIA):
  El LLM recibe los datos como tabla en el system prompt pero asocia mal las fechas con los valores, especialmente el primer punto del rango. Parece tomar el ultimo valor del trace y asociarlo al primer mes. Posible confusión por el orden cronologico o por el excerpt de tabla que solo muestra los ultimos 3 puntos.

- **Accion recomendada:**
