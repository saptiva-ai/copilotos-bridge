### FDBK-0199 — Distribución porcentual de etapas (S0, data wrong)

**Query**: "Muestra la distribución porcentual de etapas de cartera total (Etapa 1, 2, 3) para dic 2025, 10 bancos, barras apiladas 100%"
**Resultado**: "No encontré datos" — chart_status=empty, metric=CARTERA_TOTAL
**Feedback**: "no desplego la informacion de los datos"

**Hipótesis raíz**: El parser/router no reconoce "distribución porcentual de etapas" como una métrica válida. El keyword "cartera total" en el query domina y rutea a CARTERA_TOTAL genérico, que no tiene sub-métricas de etapas. El handler que debería responder (probablemente `CarteraActividadHandler` o un handler de concentración/etapas) nunca es evaluado. La combinación "etapas + multi-banco + barras apiladas" requiere un handler especializado que puede no existir.

**Componente responsable**: query_spec_parser.py (parsing de métrica) + query_router.py (selección de handler)
**Severidad**: S0 — datos completamente ausentes

**Componente responsable**: query_spec_parser.py (mapping de métrica) + handler fallback logic
**Severidad**: S0 — métrica completamente equivocada + bancos expandidos incorrectamente

**Query**: "Muestra la TDA de cartera total para dic 2025, 10 bancos, barras horizontales, INVEX en rojo"

**Hipótesis raíz**: "TDA de cartera total" se parsea como `metric=CARTERA_TOTAL` porque el keyword "cartera total" tiene mayor peso que "TDA". La respuesta muestra montos en MDP con chart_status=success para 21 bancos — mismo patrón que FDBK-0200. El handler ejecutó correctamente la consulta de cartera total, pero la consulta debía ser TDA (%).

**Componente responsable**: query_spec_parser.py (extracción de métrica — "TDA" se pierde ante "cartera total")
**Severidad**: S0 — métrica completamente equivocada
**Patrón conocido**: Match directo con ticket `multi-bank-comparison-routing-failures` (2026-03-06)
